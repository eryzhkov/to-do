# Правила архитектуры

## Архитектурные слои

- Придерживаться принципов гексагональной архитектуры.
- Соблюдать принципы SOLID при проектировании классов, интерфейсов и пакетов.
- Выделять следующие слои:
    - Домен (`domain`). Содержит бизнес-объекты, бизнес-правила, контракты вариантов использования (для вызова из внешних систем) и контракты взаимодействия с внешними системами, инициируемые приложением.
    - Приложение (`application`). Содержит реализации вариантов использования из домена, оркестрацию, управление бизнес-транзакциями.
    - Инфраструктура (`infrastructure`). Содержит технические детали: репозитории для работы с внешними хранилищами, publishers/consumers для работы с очередями, REST-контроллеры и прочее.

## Слой домен (domain)

- Базовый пакет: `domain`.
- Базовый пакет для бизнес-объектов: `domain.models`. Содержит бизнес-объекты: сущности, value objects, агрегаты. Не содержит JPA-аннотаций (`@Entity`, `@Table`) и зависит только от Java и, при необходимости, от `domain.exception`.
- Базовый пакет для контрактов вариантов использования: `domain.port.in`.
- Базовый пакет для контрактов взаимодействия с внешними системами: `domain.port.out`. Этот пакет содержит только интерфейсы. Их реализация располагается в `infrastructure.adapter.out`.
- Базовый пакет для ошибок (exceptions): `domain.exception`. Здесь находятся бизнес-исключения (нарушение инвариантов, бизнес-правил).
- Имена интерфейсов в пакетах `domain.port.in` должны иметь префикс-глагол и постфикс `UseCase`. Например, `RegisterUserUseCase.java`. Этот пакет содержит только интерфейсы. Их реализация располагается в `application.service`.

## Слой application

- Базовый пакет: `application`.
- Базовый пакет для реализации контрактов из `domain.port.in`: `application.service`.
- Имена классов в пакетах `application.service` должны совпадать с именами реализуемых контрактов и иметь постфикс `Impl`. Например, `RegisterUserUseCaseImpl.java`.
- Базовый пакет для ошибок (exceptions): `application.exception`. Здесь находятся исключения оркестрации (например, UseCase не может быть выполнен).
- Управление транзакциями осуществляется в `application.service` через `@Transactional`. В `infrastructure.adapter.out.persistence` аннотация не используется: транзакции открываются на уровне варианта использования, а не отдельного запроса к БД.
- `@Transactional` не должен появляться в `domain` или `infrastructure.adapter.in`.

## Слой infrastructure

- Базовый пакет: `infrastructure`.
- Базовый пакет для реализаций адаптеров для внешних систем: `infrastructure.adapter`. Этот пакет не содержит классов, только подпакеты.
- Адаптеры для вызова из внешних систем располагаются в подпакетах`infrastructure.adapter.in.<em>`. Имя подпакета отражает тип входящего канала(например, `rest` для HTTP, `messaging` для Kafka).
- Базовый пакет для реализаций адаптеров взаимодействия с внешними системами: `infrastructure.adapter.out`.
- Реализации интерфейсов из `domain.port.out` располагаются в подпакетах`infrastructure.adapter.out.</em>`. Имя подпакета отражает тип внешней системы(например, `persistence` для БД, `messaging` для отправки сообщений).
- Базовый пакет для ошибок (exceptions): `infrastructure.exception`. Здесь находятся технические исключения (ошибки БД, Kafka, сети).
- Базовый пакет для Java-конфигураций: `infrastructure.config`.
- Классы в пакете `infrastructure.config` должны иметь постфикс `Configuration`. Например, `KafkaConfiguration.java`. Классы конфигураций содержат только бины Spring и настройки фреймворков. Бизнес-логика и адаптеры здесь не размещаются.

## Зависимости между слоями

- Слой `domain` ни от чего не зависит.
- Слой `application` зависит от `domain` слоя.
- Слой `infrastructure` зависит от `domain` слоя.
- Слой `application` не должен зависеть от `infrastructure`.
- Слой `application` не должен зависеть от деталей инфраструктуры (JPA, Kafka, REST).
- Классы в `infrastructure.adapter.in.` вызывают контракты из `domain.port.in`.
- Классы в `infrastructure.adapter.out.` реализуют контракты из `domain.port.out`.
- `infrastructure.adapter.in.*` зависит только от `domain.port.in`, но не от `application.service`.

**Примечание**: допускается зависимость слоя `application` от Spring Boot.
