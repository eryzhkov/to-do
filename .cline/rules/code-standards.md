# Стандарты кода

## Стиль

- Следуй [Google Java Style Guide](https://google.github.io/styleguide/javaguide.html)
- Отступ: 4 пробела (не табы).
- Максимальная длина строки: 120.

## Современные возможности Java 21

- Использовать `var` только там, где тип очевиден из контекста (например, `var user = userRepository.findById(id).orElseThrow(UserNotFoundException::new);`). Избегать `var` для возвращаемых типов из репозиториев — явность важнее.
- Для неизменяемых DTO и value objects использовать `record` вместо классов с Lombok `@Value`.
- Использовать pattern matching для `instanceof` и `switch`, где это упрощает код.
- Использовать `Optional<T>` только для возвращаемых значений методов.Не использовать `Optional` для полей, параметров и элементов коллекций.Никогда не возвращать `null` из public API методов — использовать `Optional`или бросать исключение.
- Предпочитать неизменяемые коллекции: `List.of()`, `Map.of()`, `Set.of()`.

## Обработка исключений

- Не подавлять исключения (пустой `catch` блок). Если исключение не обрабатывается, оно должно быть залогировано или проброшено.
- Для бизнес-ошибок использовать исключения из `domain.exception`, для технических — из `infrastructure.exception`. Не создавать generic `RuntimeException` в бизнес-коде.
- В `@Transactional` методах учитывать, что rollback происходит только для `RuntimeException`. Проверяемые исключения не откатывают транзакцию по умолчанию.

## Логирование

- В логах использовать параметризованные сообщения: `log.info("User {} created", userId)`, а не конкатенацию строк.
- Для простых аргументов (поля, переменные) используйте параметризованное логирование (`log.debug("User {}", user)`) без `isDebugEnabled()` — Logback откладывает `toString()` до подтверждения уровня.
- Оборачивайте вызов в `if (log.isDebugEnabled())` **только если** аргумент требует дорогостоящего вычисления (вызов метода, построение сложного объекта, обращение к БД). Параметризованное логирование спасает от `toString()`, но не от вычисления аргумента.
- Для DEBUG-сообщений внутри циклов или методов, вызываемых очень часто, проверка `isDebugEnabled()` оправдана даже при простых аргументах — чтобы избежать накладных расходов на проверку уровня при каждой итерации.
- Не логировать чувствительные данные (пароли, токены, PII).

## Тестирование

- Имена тестовых методов: `methodName_condition_expectedResult` (например, `findById_whenUserExists_returnsUser`).
- Использовать `@DisplayName` на русском для читаемости отчётов.
- Для assertions использовать AssertJ: `assertThat(actual).isEqualTo(expected)`.

## Правила для Liquibase

- Все файлы миграций должны находиться строго в `src/main/resources/db/changelog/`.
- Используй формат **XML** для changelog-файлов.
- Именуй файлы по паттерну: `db.changelog-YYYYMMDD-HHMM-[short-description].xml`.
- Каждая миграция должна иметь уникальный `id` и `author: cline`.
- Каждая миграция должна иметь тег `comment` с кратким описанием изменений.
- Каждая миграция должна начинаться с тега `preconditions`. В этом теге надо проверять возможность применения изменений.
  Например, если миграция создает новую таблицу, то надо проверить, что она не существует. Если проверка завершается 
  неудачно, то ее надо пометить MARK_RUN. 
- Всегда закладывай валидные типы данных для PostgreSQL (например, `type: uuid`, `type: varchar(255)`). Не пиши сырой 
SQL в миграциях без крайней необходимости, используй стандартные теги Liquibase (`createTable`, `addColumn`).

## Запрещённые практики

- `System.out.println` — только через логгер.
- Wildcard-импорты (`import java.util.*`) — только явные импорты.
- `@Data` на JPA-сущностях — нарушает проксирование Hibernate. Использовать `@Getter`/`@Setter`.
- Магические числа и строки — выносить в константы.

## Что важно для этого проекта

- Все timestamp в UTC, тип `Instant`.
- Добавлять в класс аннотацию `@Slf4j` из Lombok.
- Добавлять `@ToString` из Lombok только к DTO, value objects и классам без JPA-связей. На JPA-сущностях `@ToString` не использовать — риск ленивой загрузки и рекурсии.
- Каждый class/interface/enum должен иметь Javadoc с пояснением его роли.
