# Project Brief: Todo App

## Обзор проекта
Веб-приложение для управления личными задачами. Пользователь может создавать, редактировать, отмечать выполненными и 
удалять задачи. Все задачи хранятся в базе данных и доступны только владельцу.

## Основные цели
1. Дать пользователю простой интерфейс для управления задачами.
2. Обеспечить сохранность данных между сессиями.
3. Предоставить REST API для возможной интеграции с другими клиентами.

## Ключевые функции (MVP)
- CRUD для задач: создание, чтение, обновление, удаление.
- Отметка задачи как выполненной.
- Фильтрация задач по статусу (все / активные / выполненные).
- Сортировка по дате создания и приоритету.

## Что НЕ входит в MVP
- Регистрация и аутентификация. В рамках проекта это не требуется - работать будет всегда один пользователь.
- Совместная работа над задачами.
- Напоминания и уведомления.
- Подзадачи и вложенные списки.
- Мобильное приложение.
- Интеграция с календарями.

## Технический стек
- **Backend**: Java 21, Spring Boot 4.1.1
- **БД**: PostgreSQL 17.6
- **Frontend**: React (простейший SPA, без SSR)
- **Сборка**: Maven

## Целевая аудитория
- Один пользователь (личное использование).
- Не предполагается многопользовательская работа в рамках одного аккаунта.

## Критерии успеха
- Пользователь может зарегистрироваться и войти.
- Пользователь может создать задачу и увидеть её в списке.
- Данные сохраняются после перезапуска приложения.
- API возвращает корректные HTTP-коды и JSON-ответы.
- Все ключевые сценарии покрыты тестами.

## Ограничения
- Приложение не рассчитано на высокую нагрузку (до 100 задач на пользователя).
- Нет требований к горизонтальному масштабированию.
- Нет требований к офлайн-режиму.

## Основные бизнес-объекты
- **TaskStatus**: допустимые состояния задачи (PLANNED, DONE). Поля: `id`, `code`, `name`.
- **TaskPriority**: допустимые приоритеты задачи (LOW, MEDIUM, HIGH). Поля: `id`, `code`, `name`.
- **Task**: задача. Поля: `id`, `title`, `description`, `status`,
  `priority`, `createdAt`, `updatedAt`, `completedAt`.

## Основные сценарии
1. **Создание задачи**: пользователь вводит заголовок и описание, задача сохраняется (статус PLANNED).
2. **Изменение задачи**: пользователь меняет заголовок, описание, приоритет, задача сохраняется (изменять можно задачи только в статусе (статус PLANNED)).
2. **Просмотр списка**: пользователь видит все свои задачи, может фильтровать (фильтр по статусу, приоритету, дате создания).
3. **Отметка выполненной**: пользователь кликает чекбокс, статус меняется (исходный статус PLANNED, финальный статус DONE).
4. **Удаление задачи**: задача удаляется безвозвратно.
