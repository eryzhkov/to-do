# Основные этапы работы

## Этап 1

### Цель

Реализовать доменные объекты.

### 1. Создать enum для статусов

Создать enum для возможных статусов задачи:
- Пакет: reb.ai.todo.domain.models
- Название enum: TaskStatus
- Значения: PLANNED, DONE.

### 2. Создать enum для приоритетов

Создать enum для возможных приоритетов задачи:
- Пакет: reb.ai.todo.domain.models
- Название enum: TaskPriority
- Значения: LOW, MEDIUM, HIGH

### 3. Создать класс для задачи

Создать класс для задачи:
- Пакет: reb.ai.todo.domain.models
- Название: Task
- Свойства:
  - id тип целое число (обязательное)
  - title тип строка (обязательное)
  - description тип строка (опциональное)
  - status тип TaskStatus обязательное
  - priority тип TaskPriority
  - createdAt тип Instant (обязательное)
  - updatedAt тип Instant
  - completedAt тип Instant

Для создания новых объектов типа Task реализовать статический метод of(), принимающий следующие параметры:
- title
- description

Метод of() сам задает значения для остальных свойств:
- id надо оставить null так как это новый объект и конкретное значение будет определено потом при сохранении в базу данных
- status надо выставить в PLANNED
- priority надо выставить в  MEDIUM
- createdAt надо выставить в текущее время
- updatedAt оставить null
- completedAt оставить null

Класс Task должен иметь следующие бизнес-методы:
- setLowPriority()
  - меняет приоритет задачи на LOW. 
  - устанавливает updatedAt в текущее время.
  - выбрасывает ошибку, если текущий статус DONE.
- setMediumPriority() 
  - меняет приоритет задачи на MEDIUM. 
  - устанавливает updatedAt в текущее время. 
  - выбрасывает ошибку, если текущий статус DONE.
- setHighPriority(): 
  - меняет приоритет задачи на HIGH.
  - устанавливает updatedAt в текущее время. 
  - выбрасывает ошибку, если текущий статус DONE.
- done(): 
  - завершает задачу, изменяя статус с PLANNED на DONE.
  - устанавливает completedAt в текущее время

### 4. Создать Unit Tests

- Проверить happy-сценарии.
- Проверить, что нельзя создать новый объект в некорректном состоянии.
- Проверить, что нельзя изменить приоритет задачи, если она завершена.

- Создавать таблицы в базе данных

### Критерии завершенности

- Проект компилируется без ошибок.
- Все тесты проходят без ошибок.
